# RootRecall 项目介绍

> *Light on every root cause.*
>
> 用途:对外介绍本项目的功能、特色与关键技术实现 —— 面向同事、面试官或技术分享。
> 30 秒电梯版见 §0;要动手用看 [README](../README.md)。

## 0. 30 秒电梯版

RootRecall 是给系统软件 C 代码库(wpa_supplicant / bluez 这类几十万行的底层仓)做「**带记忆的
bug 根因定位 + 深度调研**」的 MCP 工具服务器。它挂在任意 coding agent(opencode,兼容
Claude Code / Cursor 等 MCP 客户端)上,把 agent 本来不会的五样东西——**跨会话记忆、防幻觉的
代码检索、确定性的 git 取证、交付硬门、标准办案流程**——变成它随手可调的能力。

一个画面:在只放了一份问题 txt 的空目录里启动 opencode,说一句「分析 bluez 5.50.2 这个 SDP
解析越界 bug 的根因,修复并落报告」——agent 自动路由、自动开出该版本的仓、多假设证伪定位根因、
修复并验证 apply、教训带着验证状态入记忆;补丁与报告**等你开口要才落盘**(这句话点名了「落报告」,
便一并交付)。全程不问路径,零人工干预。

## 1. 解决什么问题

三个真实痛点,每个都有一线工程背景:

1. **coding agent 每开新会话就失忆。** 上次定位过的 bug、上次摸清的模块结构全忘,同样的代码
   从头读,费 token 又费时间;团队积累的修法经验没有沉淀载体。
2. **通用 agent 在大 C 仓里定位根因容易出错。** 项目实测:它会锚定日志里最显眼的 ERROR 行当
   根因(真因往往是更早一条安静的 INFO),会编造不存在的文件路径,会把「补丁能打上」当成
   「修对了」。
3. **系统软件没有可信的本地验证 oracle。** 没有单测、基线本身就编不过,自动试编译的信号是
   歧义的 —— 「验证」这件事必须显式划边界。

## 2. 功能全景

### 2.1 十七个 MCP 工具(agent 直接调用的「手」)

| 组 | 工具 | 干什么 |
|---|---|---|
| 记忆(3) | `memory_recall` / `memory_memorize` / `memory_dump` | 检索、写入、全量审计带溯源的知识库 |
| 代码情报(8) | `search_codebase` / `blast_radius` / `call_chain` / `repo_map` / `repo_overview` / `cross_version_diff` / `merge_eval` / `when_introduced` | 语义检索、改动影响面、调用链、全仓符号地图、架构俯瞰、版本差异、上游合入三态判定、缺陷引入史 |
| 硬门(3) | `validate_patch` / `export_patch` / `export_report` | 交付关卡:补丁必须干净 apply;落盘由用户触发(「生成补丁 / 报告」)—— 聊天回复不算交付 |
| PR 抓取(2) | `fetch_patch` / `ensure_repo` | GitHub / Gerrit PR 抓取、仓库自动落地 |
| 开仓(1) | `find_repo` | 「项目+版本」→ 注册表候选仓;没开过仓就给一条可原样执行的开仓命令 |

### 2.2 八套标准流程 skill(教 agent「怎么组合工具」的菜谱)

自然语言提问,agent 按路由表([AGENTS.md](../AGENTS.md))自动载入,不用人工选模式:

| 用户问的是… | skill | 产出 |
|---|---|---|
| 「为什么 X 会断/泄漏/死锁/崩」 | `bug-rca` | 根因 + 补丁(已验 apply)+ 报告 + 教训入库 |
| 「这个补丁/PR 干啥、能不能合」 | `patch-review` | 补丁鉴定四问:干啥/贴得上吗/波及谁/该不该合 |
| 「上游这些 commit 哪些该合」 | `upstream-merge` | 逐 commit 三态判定 + 相关性 + 决策表 |
| 「v25 修了、v20 还没修,帮我改 v20」 | `backport` | 语义判 v20 有无同一 bug → 适配出补丁 |
| 「v20 和 v25 在 X 流程上有什么差异」 | `compare` | 锚定入口逐节点对照,流程级差异报告 |
| 「这个仓整体架构怎么组织」 | `onboarding` | 结构图俯瞰 + 沿一条主旅程端到端导览 |
| 「蓝牙协议怎么设计的/记个技术笔记」 | `domain-research` | 联网多源交叉,领域知识入记忆 |
| 「记忆库质量怎么样」 | `memory-health-check` | 全量记忆逐条审计,健康信号与建议 |

### 2.3 仓库生命周期管理(多代码库的资产层)

注册表(`data/repos.yaml`)把「索引名↔仓库路径↔角色↔bug 号」串成一条链:

- **baseline(共享基线)**:永久保留;`baseline sync` 定时 fetch → fast-forward → 增量刷索引 →
  上游三态分析报告(纯 git 零 LLM),可加 headless agent 复核「该不该合」、报告摄取入记忆;
  systemd timer 样例见 [deploy/](../deploy/)。
- **ephemeral(一次性 bug 仓)**:`baseline checkout --from <基线> --ref <tag> --index` 秒开
  (bare 镜像 + worktree 共享对象库,播种基线索引只重嵌差异文件);分析完到期 gc 级联回收,
  交付物按 bug 号归档,回收后仍可追溯。
- **unmanaged**:外部样机等不碰的仓。

日常入口是 `baseline add <代码仓路径>` 一条命令:登记基线(git url/branch 自动读)+ 建索引,
默认名按代码仓总目录(`ROOTRECALL_CODEBASES`,quickstart 建,默认 `~/codebases`)的相对路径
倒序生成(`v20/bluez` → `bluez-v20`、`systemd` → `systemd`)。

### 2.4 部署面

quickstart 一键装机(零 key 也能跑最小模式:记忆 + 仓库管理);`install --global` 装一次、
任意目录直接问;`ROOTRECALL_HOME` 数据整体迁出安装根;装机链经干净机演练(零 key / 全功能两轮)。

## 3. 特色(与通用方案的差异化)

1. **记忆带代码级溯源。** 每条知识带 file:line 证据 + commit_sha + 置信度 + 双时间轴。
   通用 agent memory(Graphiti / mem0 / Zep)记的是「用户说过的话」,没有代码锚点 ——
   而模型敢不敢用一条记忆下根因判断,取决于能不能追到「哪个 commit、哪个文件第几行」。
2. **记忆会自我治理。** 纠正闭环(新旧结论并存、旧条降权 0.3 不删、审计可回溯)、五道巩固
   pass(高频教训升级成 mental_model、矛盾对标记待裁决、已合入上游打折、语义近邻报候选、
   过期标记)、专门的体检 skill。记忆越用越准,而不是越攒越乱。
3. **验证状态是结构化的,不靠自觉。** apply 过即可早记教训,但工具层强制打 `unverified`
   标、置信封顶 0.5,召回时显式渲染「(未真机验证)」;真机验证通过后**同一补丁重提一次**
   即原地升级(`real_machine`)。教训不憋着,没坐实的永远看得出来。
4. **确定性与语义的分工是设计出来的。** git / 图系工具只出确定性地板(三态、影响面、引入
   候选),「真根因是谁、该不该合」的裁决留给 agent 结合读码做 —— 每组工具的边界显式声明。
5. **recall-first + 命中短路。** 所有流程第一步翻记忆,命中同主题直接复用出报告。实测把一次
   重复调研从 42 次工具调用压到 4 次(约 7×),质量不降。
6. **诚实信号贯穿。** 截断必带「截了多少、怎么补取」;工具降级必注明;报告永不谎报
   tested / verified;自动验证封顶在 apply,编译 / 复现 / 真机归工程师 —— 边界写在产品里。

## 4. 关键技术实现

**检索管线(代码情报的底座)**
tree-sitter 按符号边界切块(函数一块、类一块),块头拼文件/符号注释行再嵌入(Anthropic
Contextual Retrieval 的轻量版)→ BM25(FTS5)+ 向量(LanceDB)两路召回、RRF 融合 →
cross-encoder 对**全量候选**精排(不只前 k 个)→ 符号粒度先验微调(module 块与私有符号
降权、公共入口不动;L1 自评测 rprecision@5 = 1.000)。增量按 manifest 的 sha256 对账,
只重嵌改动文件、清幽灵行;小版本索引可从基线**播种**(拷贝后只重嵌差异,省 95%+ 嵌入费)。
文件遍历尊重 .gitignore(参考仓不白付嵌入费)。

**结构图**
code-review-graph 把全仓解析成函数调用图存 SQLite,上面跑三类经典算法:PageRank(符号
重要性)、Leiden 社区检测(模块边界)、介数(咽喉节点)。blast_radius / call_chain /
repo_map / repo_overview 全是纯图查询 —— 零 LLM、天然防幻觉。

**记忆后端**
SQLite + FTS5 + jieba 中文分词(索引 / 查询两侧同切,中文查询 BM25 才命中)+ sqlite-vec
向量 ANN(超 500 条渐进切换)。召回是**四路融合**(记忆 BM25 / 记忆向量 / 代码索引 /
结构图)→ RRF → 可选精排 → 时间衰减 × Bayes 置信 × 纠正降权。写入内容寻址(同补丁重提
同 id 合并增强)—— 这让「真机验证后升级」不需要编辑旧条,天然成立。

**git 确定性工具**
上游合入三态:`--cherry-pick` 对称差(patch-id 等价判「已修」)+ `merge-tree --write-tree`
在对象库试合并判冲突(**零 touch 工作树**,不要求干净树)。缺陷引入史:pickaxe(`-S`
符号)/ 行历史(`-L`,改名跟随)双锚点出候选表,「哪条真引入了缺陷」归 agent 裁决 ——
SZZ 式分工。

**架构形态**
委托型 —— RootRecall 不调度 agent、不做平行定位管线(建过又砍掉),
读码改码等重活全归宿主 agent,自己只做宿主做不好的事。17 个工具可用 `ROOTRECALL_MCP_TOOLS`
门控裁剪(minimal 8 / research 12 / full 17 或逗号清单;未注册不进 tools/list,真省上下文)。

## 5. 质量与验证

356 个 pytest 全绿 + ruff clean 只是底座;更硬的是**多轮金标准对照的真 e2e**:

- wpa P2P 泄漏 bug:agent 诊断与人工金标逐文件逐行一致,含用时序证伪淘汰错误假设;
- bluez SDP 整数溢出:一句话定位,根因与上游修复逐字一致;backport 三个安全修复语义判定全中;
- 调研报告 80~267 条 file:line 引用人工核验,**零幻觉**;
- 记忆在行动链上真实变现:backport 时 recall 直接给出 v20 的三个文件路径线索(来自此前的
  同步分析报告摄取);
- 装机链经干净机演练(一次演练抓出三条「只在用户环境才炸」的 bug,方法论沉淀为踩坑短篇);
- 验证全部为**私有真机金标**,不经公开基准 —— 在 SWE-bench 记忆污染被证实的年代(模型只看 issue
  文本即可 76% 命中出错文件),无污染的证据链本身就是质量声明。
